11. Tests and settings

A test calls the app without starting uvicorn. TestClient pretends to be a browser.

python -m pip install httpx
from fastapi.testclient import TestClient
from main import app

client = TestClient(app)

def test_home():
    response = client.get("/")
    assert response.status_code == 200
    assert response.json() == {"message": "hello"}

def test_missing_task():
    response = client.get("/tasks/999")
    assert response.status_code == 404

Override a dependency so tests do not touch the real database or the real login. The test passes a fake.

def fake_user():
    return {"id": 1}

app.dependency_overrides[get_current_user] = fake_user

Clear overrides at the end of the test, or later tests inherit the fake. A database test uses a separate SQLite file, or an in-memory engine, created in a fixture and thrown away after. Do not point tests at the database your evening project is using.

What to test first: the happy create, the 404, the 422 from a blank title, and one protected route without a token, which must be 401. That is enough to trust the menu. You are not testing FastAPI. You are testing your rules.

Settings

Secrets and machine-specific values stay out of the code. A .env file holds them locally and is listed in .gitignore. The process reads them from the environment.

python -m pip install pydantic-settings
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env")
    secret_key: str
    database_url: str = "sqlite:///./tasks.db"

settings = Settings()

A .env file:

SECRET_KEY=change-me
DATABASE_URL=sqlite:///./tasks.db

Names are matched without caring about case. If SECRET_KEY is missing, the app refuses to start. That is what you want. A default secret that ships in git is how a token gets forged.

12. A day of building one resource

Build tasks, in this order. Each step runs before you add the next. If you add login and the database and files on the same afternoon, you will not know which piece failed.

  1. A dict and four routes: list, create, read, delete. Open /docs and click them.
  2. Replace the dict argument with TaskIn and response_model=TaskOut. Send a blank title and watch 422.
  3. Raise 404 for a missing id. Test it with TestClient.
  4. Move the routes onto a router and include it from main.py.
  5. Swap the dict for SQLite. The session comes from Depends.
  6. Add /token and put get_current_user on create and delete. List can stay public for the lesson.
  7. Add CORS only when a browser page on another port calls you.

A request walks this line. Client, router, dependencies, your function, database, response model, JSON. When something breaks, point at the step. 422 is the shape, before your function. 404 is your function. 401 is the user dependency. 500 is an exception you did not translate, so read the traceback.

The slips

  • Blocking call inside async def. Use def, or an async database driver and await.
  • One global session. Create a session per request and close it in finally.
  • Returning the SQLAlchemy row with a secret column and no response_model. The whole object can leak. Set the response model.
  • Password stored as text. Store a password hash.
  • Secret key in the file you commit. Read it from the environment.
  • /tasks/{task_id} declared above /tasks/count. The word count is captured as an id. Fixed paths go first.
  • Forgetting commit. The row exists only in the session and vanishes.
  • CORS added to please curl. curl was never blocked. Look at the browser console. The origin must match exactly, including the port.
  • A test that uses the real tasks.db. Override the session dependency.

13. Interview questions and answers

What is FastAPI? A Python web framework that turns type hints into request checking, JSON responses, and automatic docs. A path function is one menu entry.

What is the difference between path, query, and body? The path is part of the URL and identifies the resource, /tasks/3. The query is the filter after ?. The body is the JSON parcel, described by a Pydantic model.

Why 422? The request reached the app and failed validation: wrong type, missing field, or a field rule. Your function did not run. 400 is for a rule you enforce yourself inside the function.

What does response_model do? It filters and documents the output. Extra fields on the object you return are dropped. That is how a password hash stays off the wire.

def or async def? def runs in a thread pool and may call blocking libraries. async def runs on the event loop and must await instead of blocking. A blocking call inside async def stalls other requests.

What is Depends? A function FastAPI runs for you and injects into the path. Use it for the database session, paging, and the current user. yield dependencies get a cleanup step after the response.

How does login work? POST /token checks a password against a hash and returns a signed JWT. Later requests send Authorization: Bearer. A dependency decodes the token and raises 401 when the signature or the expiry fails.

Why hash passwords? A stolen database of hashes is not a list of passwords. You store a slow password hash, bcrypt or Argon2, and check new attempts against it. You cannot read the original password back, and you should not be able to.

What is CORS? A browser refusing to let a page on one origin read a response from another origin, unless the API allows that origin. Tools that are not browsers skip this check.

How do you test a route? TestClient calls the app in process. Override dependencies so the test supplies a fake user and a throwaway database. Assert the status code and the JSON.

Where do settings live? In the environment, read by a settings object. The secret key is not a string in git.

SQLite or MongoDB? SQLite, through SQLAlchemy, stores rows in tables and gives you integer ids and commit. MongoDB stores documents in a collection. The id is an ObjectId you send as a string, and insert_one writes immediately. The routes and the Pydantic models stay the same. Only the load and save lines change. Use one of them while you learn the menu.

When do you not use BackgroundTasks? When the work must survive a crash. Use a real queue. Background tasks run after the response, in the same process, and die with it.

You have the map

A FastAPI app is a menu of functions. Types and Pydantic check the request. The response model checks what leaves. Dependencies hand in the session and the user. The database remembers the rows. Login is a password hash plus a short-lived token. Tests call the menu without the network. Everything else, files, CORS, sockets, and background work, is a specific kind of request or a specific kind of after-work.

Build the task resource in the order in chapter 12. When a status code appears, you already know which step produced it.
