datetime

A naive datetime has no timezone. An aware datetime has one. Mix them and Python raises, which is the right failure. Store instants as aware UTC. Convert to a local zone only for display.

from datetime import datetime, timezone
now = datetime.now(timezone.utc)
stamp = now.isoformat()

date is a calendar day. timedelta is a duration. Subtracting two datetimes returns a timedelta.

collections

from collections import Counter, defaultdict, deque

counts.most_common(1)

groups["priya"].append(1)

line.append(1)
line.appendleft(0)

re

A regular expression is a tiny language for text shapes. re.search finds a match anywhere. re.fullmatch requires the whole string to match. re.findall returns the matched pieces. Compile a pattern you reuse. Prefer string methods when the job is a fixed prefix, suffix, or split. Reach for re when the shape varies: an email-like token, a repeated number, optional pieces.

import re
match = re.fullmatch(r"[A-Z]{2}\d{2}", "KA01")
code = match.group(0) if match else None

logging

Levels, from quieter to louder: DEBUG, INFO, WARNING, ERROR, CRITICAL. Configure once at program start. Get a logger per module with logging.getLogger(__name__). Log an event with fields, not a paragraph you will regret parsing.

import logging
log = logging.getLogger(__name__)
log.info("opened code=%s", code)

The %s style lets the logger skip the formatting work when the level is disabled. Pass exceptions with log.exception("save failed") inside an except block so the traceback is recorded.

argparse and subprocess

import argparse
parser = argparse.ArgumentParser()
parser.add_argument("path")
parser.add_argument("--limit", type=int, default=10)
args = parser.parse_args()

subprocess.run(["python", "tool.py"], check=True) runs a program and raises if it exits with an error. Pass arguments as a list. A single string with shell=True hands that string to a shell, which is how untrusted text becomes a command. Keep shell=False unless you have a specific reason and a trusted command.

random and secrets

random is for games, samples, and tests. It is not for passwords or tokens. secrets.token_urlsafe(16) and secrets.choice draw from the operating system’s cryptographic source. Seeds exist so a simulation can be repeated: random.seed(0).

19. Concurrency

Concurrency means the program has more than one thing in progress. It does not always mean more than one CPU core is running your Python at the same instant.

The GIL

CPython, the usual interpreter, has a global interpreter lock. One thread at a time runs Python bytecode. Threads still help when the work waits on the network, a disk, or a database, because those waits release the lock and another thread can run. Threads do not speed up a tight loop of pure Python arithmetic. For that, use separate processes, or a library that does the heavy work in native code and releases the lock.

Threads

A Thread runs a function beside the caller. Share objects only with a plan. A lock (threading.Lock) lets one thread into a block at a time. Acquire locks in a fixed order so two threads cannot each hold the lock the other wants. Prefer handing each thread its own data and collecting results through a queue.Queue.

from threading import Thread

def work(name, out):
    out.append(name.upper())

box = []
thread = Thread(target=work, args=("priya", box))
thread.start()
thread.join()

The list append here is one bytecode operation and is safe in CPython. A read-modify-write such as n = n + 1 on a shared n is not safe. Use a lock or a queue.

Processes

multiprocessing and concurrent.futures.ProcessPoolExecutor run functions in other interpreters, each with its own GIL. Arguments and return values are pickled, which means copied across a boundary. Processes pay startup cost and cannot share an ordinary list. Use them for CPU-heavy work that splits into independent chunks.

from concurrent.futures import ProcessPoolExecutor

def square(n):
    return n * n

if __name__ == "__main__":
    with ProcessPoolExecutor() as pool:
        print(list(pool.map(square, [1, 2, 3])))

The __main__ guard is required on Windows. The child process imports the module, and without the guard it would spawn more children forever.

asyncio

async and await are cooperative concurrency on one thread. A task runs until it awaits something, usually I/O. The event loop then runs another task. Nothing preempts you. A CPU loop or a blocking time.sleep inside an async function freezes every task. Use asyncio.sleep, async libraries, and asyncio.to_thread for a blocking call you cannot avoid.

import asyncio

async def fetch(name):
    await asyncio.sleep(0.1)
    return name.upper()

async def main():
    results = await asyncio.gather(fetch("a"), fetch("b"))
    return results

asyncio.run(main())

gather starts the tasks together and waits for all of them. One event loop per thread is the rule. asyncio.run creates the loop, runs the coroutine, and closes the loop.

Choose by the bottleneck. Waiting on many sockets: asyncio or threads. Burning CPU in Python: processes. A single straightforward script: neither.

20. Tests, debugging, and style

Tests

A test calls a function with a fixed input and checks the output. pytest is the tool most projects use. A test is a function whose name starts with test_, and a failing assert is a failing test.

def clamp(n, low, high):
    return max(low, min(high, n))

def test_clamp_low():
    assert clamp(-1, 0, 10) == 0

def test_clamp_inside():
    assert clamp(4, 0, 10) == 4

Run python -m pytest. Test the edges: empty input, one item, the boundary value, the error case. For exceptions:

import pytest

def test_rejects_blank():
    with pytest.raises(ValueError):
        parse(" ")

The standard library’s unittest does the same job with classes and self.assertEqual. Knowing either is enough. Mock only the edges you do not own: the clock, the network, a random source. A test that mocks the function it claims to test proves nothing.

Give tests a fake clock and a fake repository, the same idea as the system-design book. Pass them in. Do not make the function reach for a hidden global that the test cannot replace.

Debugging

Read the traceback first. Then print the value you did not expect, or drop into the debugger with breakpoint(). From there, n steps to the next line, s steps into a call, c continues, p expr prints an expression. repr(value) shows a value more honestly than print when spaces and types matter.

Bisect a mystery: comment half the path, or return early, until the surprise disappears. The last piece you removed is where to look.

Style

PEP 8 is the community style. The parts that matter daily:

  • Four spaces per indent. Lines around 88 or 99 characters, not a hard religion.
  • Functions and variables in snake_case. Classes in CapWords. Constants in UPPER_SNAKE.
  • Two blank lines between top-level functions and classes.
  • Imports in three groups: standard library, third party, your package. One import per line for modules. Avoid from module import *.
  • Names that say what the value is. elapsed_seconds beats t once a function is longer than a few lines.
  • A function does one job. If you describe it with “and,” consider splitting it.
  • Raise specific exceptions. Return None only when absence is a normal answer, and hint | None.

Formatters such as ruff format or black end arguments about whitespace. Linters such as ruff catch unused names, shadowing, and mutable defaults. Run them. They are part of knowing the language in a team.

21. Pitfalls

These are the mistakes that happen after the syntax is familiar.

  • Shared mutable default. def f(items=[]) uses one list forever. Use None and create the list inside.
  • Alias versus copy. b = a shares a mutable object. Copy when you mean a separate value.
  • Late closure. Lambdas in a loop share the loop variable. Bind it with a default argument.
  • is for values. Use is for None. Use == for everything you mean as a value. Small integers may share objects by accident. Do not depend on that.
  • Float money. Use Decimal.
  • Mutable dict keys. Only hashables. Do not change an object that is already in a set.
  • Modifying a list while looping over it. Iterate over a copy, or build a new list.
  • Except that is too wide, then a bug disappears into the handler. Catch the type you expect.
  • Bare open without with and without an encoding.
  • Naive and aware datetimes mixed in one expression.
  • Shadowing a builtin. Naming a variable list or id hides the builtin in that scope.
  • A module named like the standard library, such as random.py in your folder.
  • Forgetting the main guard before using multiprocessing on Windows.
  • Blocking inside async def. The whole loop waits with you.
  • Caching a function that is not pure.
  • Comparing floats with == after arithmetic. Compare with a tolerance, or use decimals.
  • Assuming dict order did not exist. It does, since 3.7. Still do not use a dict as a priority queue. Use a heap (heapq) when you always need the smallest item.
import heapq
heap = []
heapq.heappush(heap, (2, "b"))
heapq.heappush(heap, (1, "a"))
first = heapq.heappop(heap)   # (1, "a")

What “I know Python” means

You can write a small program that reads a file, computes with dicts and lists, defines a function and a class, handles a bad input with an exception, and tests the function. You can explain why two names saw the same list change. You can say when you want a thread, a process, or async. You can read a traceback. That is the language. Libraries for the web, data, or machine learning sit on top of this map. They are vocabularies of functions. They are not a second language.

Ten sessions

  1. Names, mutability, is and ==. Draw boxes and arrows for three tiny programs.
  2. Strings, f-strings, slices, and a file read with pathlib.
  3. Lists, dicts, sets, comprehensions. Solve “count the words in a file.”
  4. Functions, defaults, *args, scope, and the closure trap.
  5. Exceptions. Turn the word count into a function that raises on a missing file and returns a Counter.
  6. Classes, dataclass, property, inheritance. Model a ticket with close.
  7. Generators and with. Stream the word count so the whole file is not one string if you can avoid it. Line by line already does this.
  8. A decorator that times a function, using wraps. Add lru_cache to a pure function and show a second call is instant.
  9. Type hints on the word counter. Run a type checker if one is installed.
  10. One test file with pytest. One threaded or async example that waits, and one sentence on why a CPU loop would not speed up under threads.

After those ten, pick a project you care about and keep this PDF closed until a concept fails you. Then open that chapter only. The concepts are the ones in the contents. Knowing them is predicting the next line, not recognizing the heading.
