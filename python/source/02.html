11. Errors

An exception is how Python reports that a statement could not finish. The traceback shows the call stack, newest call last. Read it from the bottom: the exception type, the message, and the line that raised it. Then walk upward to see who called that line.

try:
    value = int(text)
except ValueError:
    value = None
else:
    print("parsed", value)
finally:
    print("done")

except runs when that exception type is raised. else runs when the try body did not raise. finally runs either way, including after return. Use finally or, better, with, to release a resource.

Catch the narrowest type that you can handle. A bare except: also catches KeyboardInterrupt and SystemExit, which inherit from BaseException rather than Exception. Catch Exception only at a boundary where you log and continue or exit cleanly.

Raise with raise ValueError("amount must be positive"). Chain causes with raise RuntimeError("could not save") from error so the original traceback stays attached. raise with nothing, inside an except, re-raises the current exception.

Define your own type when callers should be able to catch that case on purpose.

class Full(Exception):
    pass

def park():
    raise Full("no spots")

Python style prefers EAFP, “easier to ask forgiveness than permission”: try the operation and handle the exception. The other style, LBYL, checks first (“look before you leap”). A check-then-act pair can still fail if the world changes between the check and the act. Catching KeyError or FileNotFoundError is often the honest version.

12. Classes

A class is a blueprint. An instance is one built object. self is the instance the method was called on. You list it as the first parameter. You do not pass it at the call: ticket.leave() passes ticket as self.

class Ticket:
    def __init__(self, plate, entry):
        self.plate = plate
        self.entry = entry
        self.exit = None

    def close(self, now):
        self.exit = now
        return now - self.entry

ticket = Ticket("KA01", 10)
ticket.close(25)

__init__ initializes a new instance. It does not return the instance. Python creates the instance, then calls __init__.

Attributes set on self belong to that instance. Attributes set on the class are shared.

class Lot:
    city = "Pune"          # shared
    def __init__(self):
        self.spots = []    # per instance

A mutable class attribute, such as a list defined on the class, is one list for every instance that does not override it. Put per-instance containers on self inside __init__.

Methods

An ordinary method receives the instance. A @classmethod receives the class, and is how you write an alternate constructor. A @staticmethod receives neither. It is a function parked in the class because it belongs to that topic. Prefer a module-level function when it does not need the class at all.

class Link:
    def __init__(self, code, url):
        self.code = code
        self.url = url

    @classmethod
    def from_pair(cls, pair):
        code, url = pair
        return cls(code, url)

A @property looks like an attribute and runs a method. Use it when reading a value should stay cheap and stable, and when replacing a stored attribute with a calculation should not break callers.

class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def area(self):
        return 3.14159 * self.radius ** 2

Inheritance

A subclass is a more specific blueprint. It reuses the superclass and can override methods. super() calls the next implementation in the method resolution order.

class Vehicle:
    def spots(self):
        return 1

class Bus(Vehicle):
    def spots(self):
        return 5

isinstance(bus, Vehicle) is true. type(bus) is Vehicle is false. Prefer isinstance when you mean “can this be treated as.”

The MRO is the order Python searches parent classes. With single inheritance it is the obvious chain. With multiple inheritance, Python uses the C3 order so each parent appears before its own parents and so a class is not visited twice. You rarely need multiple inheritance. When you do, read Class.__mro__ before you trust super().

A leading underscore, _cache, is a convention: “internal, callers should use the public method.” Two leading underscores, __cache, trigger name mangling to _ClassName__cache, which avoids accidental overrides in subclasses. It is not a security boundary. Nothing in a Python object is hidden from a determined caller.

Dataclasses and enums

A dataclass writes __init__, __repr__, and __eq__ for a class that mostly stores fields.

from dataclasses import dataclass

@dataclass
class Point:
    x: float
    y: float

    def moved(self, dx, dy):
        return Point(self.x + dx, self.y + dy)

frozen=True makes assignment to fields fail, which is what you want for a value that should be a dict key. slots=True on a dataclass stores fields more tightly and rejects accidental new attributes.

An enum is a fixed set of named constants.

from enum import Enum

class State(Enum):
    HELD = "held"
    SOLD = "sold"

Compare with is or == against the member, not against the raw string scattered through the program.

13. The data model

Python’s syntax is sugar over methods with double underscores. When you write len(box), Python calls box.__len__(). When you write a + b, it calls a.__add__(b). When you write box[0], it calls box.__getitem__(0). Implementing these methods is how your class joins the language.

__repr__ should be unambiguous, ideally a string that shows how to rebuild the value. __str__ can be friendly. If you define only __repr__, print uses it too.

If you define __eq__, Python sets __hash__ to None unless you define that too, and the objects cannot be set members or dict keys. Equal objects must have equal hashes. The hash of a mutable object is a trap, because changing the object after inserting it into a set loses the entry. Hash immutable values.

Duck typing means “if it has the methods you need, use it.” A function that calls write can accept a file, a StringIO, or your own class with write. A Protocol in the typing chapter names that shape for the type checker. An abstract base class, from abc, refuses to instantiate a subclass that forgot a required method. Use a Protocol when you want structure. Use an ABC when you want a shared base that enforces a contract.

14. Iterators, generators, and with

An iterable can produce an iterator, usually through __iter__. An iterator produces the next value through __next__ and raises StopIteration when it is done. A for loop gets an iterator and calls next until that exception. You rarely write the class form. You write a generator.

A generator is a function that uses yield. Calling it does not run the body. It returns a generator object. Each next runs until the next yield, pauses, and resumes there later. Generators produce one item at a time, so a billion-row scan does not become a billion-row list.

def countdown(n):
    while n > 0:
        yield n
        n -= 1

for value in countdown(3):
    print(value)

yield from other forwards each item from another iterable. A generator expression is the lazy cousin of a list comprehension: (n * n for n in range(10)). It does not compute the squares until something walks it. Walking it twice does nothing the second time. It is spent.

itertools holds the small tools: chain, islice, groupby, count, cycle. Reach for it before you write a nested loop that only reorganizes items.

Context managers

with guarantees cleanup. The object’s __enter__ runs at the start. __exit__ runs at the end, whether the block succeeded, returned, or raised. Files, locks, and database transactions are the usual examples.

contextlib.contextmanager lets you write one as a generator: the code before yield is enter, the code after is exit.

from contextlib import contextmanager

@contextmanager
def section(title):
    print("start", title)
    try:
        yield
    finally:
        print("end", title)

15. Decorators

A decorator is a function that takes a function and returns a function, applied with @. The two spellings below are the same.

def shout(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs).upper()
    return wrapper

@shout
def greet(name):
    return f"hello {name}"

Use functools.wraps so the wrapper keeps the original name and docstring.

import functools

def shout(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return str(func(*args, **kwargs)).upper()
    return wrapper

A decorator can take arguments by adding one more nested function: the outer function receives the arguments and returns the real decorator. Built-in decorators you will use constantly are @property, @classmethod, @staticmethod, @dataclass, and @functools.lru_cache or @functools.cache for a pure function you want to memoize. Cache only functions whose results depend only on their arguments. A cached function that reads a global or the clock will lie.

16. Modules, packages, and installs

A module is a .py file. A package is a folder of modules. import math loads the module and binds the name math. from math import sqrt binds sqrt itself. import math as m renames it locally.

Importing runs the module’s top level once and caches the module in sys.modules. A second import does not run it again. Keep the top level boring: definitions, not a program that starts work. Put the program under this guard so importing the file does not launch it:

def main():
    print("running")

if __name__ == "__main__":
    main()

__name__ is "__main__" only when that file was the one you started. When another file imports it, __name__ is the module’s name.

A package folder may contain __init__.py. That file runs when the package is imported. Relative imports, from . import codec, stay inside the package. They work when the package is imported as a package, and they fail if you run an inner file as a loose script. Run python -m package.module instead.

The import path is sys.path: the script’s directory, then installed locations. Do not modify it in ordinary programs. Name your modules so they do not shadow the standard library. A file called json.py will hide the real json.

Environments and packages

A virtual environment is a private folder of installed libraries for one project, so project A’s library version does not change project B.

python -m venv .venv
.venv\Scripts\activate
python -m pip install requests

pip installs packages from the Python Package Index and from local folders. Pin versions in a requirements file or, better for a real project, declare them in pyproject.toml. That file is also where a tool reads the project’s name, the Python version it needs, and the build backend. You do not need to publish a package to benefit from a venv and a pinned list. You need them the moment a program must run again next month.

The standard library ships with Python. Third-party packages do not. Prefer the standard library when it does the job.

17. Type hints

Hints describe the kinds of values you intend. Python does not enforce them while the program runs. A type checker such as pyright or mypy reads them as a separate step. Hints pay off in anything larger than a script: editors complete names, and a wrong argument is caught before the program runs.

def clamp(n: int, low: int, high: int) -> int:
    if n < low:
        return low
    if n > high:
        return high
    return n

def find(code: str) -> str | None:
    return codes.get(code)

str | None means a string or None. list[str], dict[str, int], and tuple[int, int] name the insides. tuple[int, ...] is a tuple of any length of ints. A bare list hint does not say what the list holds.

from collections.abc import Callable, Iterable, Sequence

def total(nums: Iterable[int]) -> int:
    return sum(nums)

def apply(fn: Callable[[int], int], n: int) -> int:
    return fn(n)

Hint the most general thing you actually use. If you only iterate, hint Iterable. If you index and take len, hint Sequence.

A Protocol names a structural shape. Any object with those methods satisfies it, with or without a shared base class.

from typing import Protocol

class Writer(Protocol):
    def write(self, text: str) -> int: ...

A TypedDict describes a dict with known keys, which is what JSON objects become. A dataclass is still the better choice when you own the type. Use TypedDict at the edge where the data really is a dict.

Generics use TypeVar or, in current Python, a type parameter: class Box[T]. You need them when a function’s result type depends on its input type, such as “this cache stores whatever type you put in.”

Casts and Any switch the checker off for that expression. Use them at a boundary you do not control, and keep them small. A hint of Any on every function is the same as no hints.
